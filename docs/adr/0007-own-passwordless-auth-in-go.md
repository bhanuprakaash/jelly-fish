# Own passwordless auth in Go

We build login ourselves in the Go backend instead of adopting Ory Kratos, Zitadel or a hosted service (Clerk, WorkOS, Supabase). Users sign in with an emailed 6-digit code (the email also carries a link) or with Google; there are no passwords. A **Login Session** is a Postgres row behind an opaque cookie, so revoking one is a delete. Reasons: it's a learning project that already owns its Event Log and queue (ADR 0001); the user base is invited friends; a separate auth server is one more thing to run and learn; hosted options gate features (Clerk puts passkeys on paid plans). Passwords are dropped because NIST 800-63-4 now asks 15 characters plus breach checks, and a reset flow would be email anyway. The cost: we own the security of login codes, cookies and CSRF ourselves, and passkeys are later work.
